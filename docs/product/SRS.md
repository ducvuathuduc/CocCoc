# Software requirements specification

Version 1, 2026-10-03. Product scope: English learning for Vietnamese-speaking university users, Flutter Android/iOS, three business services, course author CLI, offline unit practice, free-first guided speech. P0 = gate requirement; P1 = core enhancement; P2 = bounded extension. Requirement IDs never change when wording changes.

Normative rules here are our design, not undocumented Duolingo behavior. “AC” means acceptance criteria. API operation IDs appear in [OpenAPI](../api/openapi.yaml). Nonfunctional requirements and test budgets are canonical in [NFR](../architecture/NFR.md).

## Common contracts

All flows use [screens](SCREEN_INVENTORY.md), [component states](../design/COMPONENT_STATES.md) and [central failures](EDGE_CASE_MATRIX.md). Every server mutation verifies subject, validates full typed body and uses persistent idempotency. Offline feedback/XP is provisional. AI never overrides the deterministic answer key. Online API failure preserves entered answers.

## Deterministic learning and reward rules

Normal lesson has 10 original exercises. Practice may select 5–20. Exercise types: textTranslation, choice, wordBank, sentenceOrder, fillBlank, matchPairs, imageChoice, listenChoice, dictation, speakRepeat, dialogueTurn, storyQuestion. Render only these registered types; payload is content, never remote widget code.

Normalize typed text with Unicode NFC, trim, collapse whitespace, locale-aware lowercase where authored caseSensitive=false; punctuation and diacritic tolerance are explicit authored flags. English accents never invented as “typos”; Vietnamese diacritics remain significant. Match curated alternatives, never arbitrary semantic equivalence from LLM. Word-bank/order answers compare stable token IDs, including repeated-token IDs. Pair answers contain leftId/rightId matches and compare a complete set of authored connections; duplicate/unknown endpoints rejected. fillBlank uses one authored blank with a text answer in V1. A speech capability substitute uses an authored written item with identical skill tags.

For an online first completion: XP=10 + originalFirstCorrectCount (0–10) + 5 if all originals correct without hint. Offline first completion omits perfect bonus and league eligibility. A repeated lesson completion earns5 study XP, capped30 replay XP per server learning day. First-completion identity is userId+lessonVersion; re-published equivalents explicitly map rewardIdentity to prevent harvesting new versions. Maximum credited study XP/day1,200; excess remains practiced with award0. Progress owner applies the caps.

Review heuristic: intervals [1,3,7,14,30] calendar days; stage starts0. Correct unassisted review schedules current interval then advances stage capped4; wrong/assisted sets stage0 and due tomorrow. Within-session retries do not advance long-term stage. Mastery is rolling fraction of last20 first attempts per skill, minimum5 attempts before showing a percentage. Due selection sorts dueAt asc, then recent mistakes, then stable vocabularyId; interleave at most2 consecutive same-kind items. This is a transparent heuristic supported broadly by retrieval/feedback research, not an optimized scientific estimate.

Streak derives from day_activity rows with active=true or protected=true in chronological learning-day order. Display consecutive run ending today if qualified, otherwise yesterday; cap displayed history at365 days for V1. Scheduled Progress job checks missed days up to7-day catch-up, consumes available freezes in chronological order once, and stores protected day. Late delivery can mark a protected day active but never refunds a consumed freeze. Events older than7 days still record study XP/day history; reconciliation recomputes last365 days. Timezone transition never rewrites existing day keys or rewards.

League week is Monday00:00→next Monday00:00 UTC, independent of streak zone. Event committed before cutoff counts that week even if delivered late; league closes only after outbox watermark/reconciliation succeeds, otherwise status=settling. Maximum closure delay24h then manual intervention, never publish an knowingly incomplete rank. Joined cohorts are immutable for a week. Gems initialize20 once after verified profile init; no transferable/real money currency.

REVIEW/MASTERY sessions earn5 study XP under the30/day replay cap, zero league XP; PLACEMENT earns no XP/activity/quest credit. Daily “2lessons” counts LESSON mode only; reviewSessions counts REVIEW only. New course versions share rewardIdentity unless materially new content is explicitly mapped by author. Generated review bundle lessonId=review_dynamic, private snapshot≤64KB,5–20items; use session API for resume, never public bundle lookup.

Timezone command chooses effectiveAt=00:00:00Z on the UTC date immediately after server acceptance. Before that instant use prior history row; at/after use new row. Progress chooses the latest immutable history row with effectiveAt≤event.occurredAt inside the reward transaction; delayed delivery uses event server time, never processing/device time. Reconciliation uses that same rule. Display day is the later of current zone date and most recent credited/protected day, preventing a backward-travel UI regression; stored past keys stay unchanged.

## Scope exclusions and capability gates

No full translation catalog, payments/ads, live camera video, chat messaging, math/music/chess, automatic semantic grading, public-store distribution, or claimed production capacity at10,000 connections. V1 includes honest UI states for unavailable services. Cloud live/phoneme scoring becomes enabled only after P8 physical-device and account tests; the required baseline remains recorded/typed/shadowing speaking plus cached listening.
