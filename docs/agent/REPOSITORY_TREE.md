## Ownership rules

- The mobile app never shares a domain package with the services. There is no second frontend, gateway, Redis, broker, Kubernetes or web admin.
- Each service writes only its own table prefix (`l_`, `p_`, `a_`). Cross-service effects travel only as HMAC-signed events into the receiver's inbox.
- Hosted bundles (`services/*/dist/function.mjs`) contain no mock or memory code. In-memory adapters live in `src/persistence/memory.ts`, `src/testing/` and `src/dev.ts`.
- OpenAPI is the only wire contract. TypeScript types and Dart DTOs are generated from it and checked by SHA. The file is JSON content under the historical `.yaml` name. It stays that way because the Dart generator embeds the file's SHA and the Flutter round-trip test reads it as JSON.
- Secrets and private exports stay outside Git. `.env.example` lists names only.
- Generated build/cache output (`node_modules`, `dist`, `.cache`, `build`, `.dart_tool`) is ignored, including symlinked `node_modules` in worktrees.

## Known follow-ups

- Mobile: profile, league, energy and Super screens sit under `features/progress/presentation`. See the [mobile AGENTS](../../apps/mobile/AGENTS.md) note.
- `CourseManifest` in OpenAPI hard-codes the seed shape, and `LeagueTier` has 7 tiers versus 10 in DATA_MODEL. Both are open content/UI contract decisions.
- `docs/audit/INPUT_INVENTORY.json` is a dated baseline snapshot with stale hashes. It is kept as history.
