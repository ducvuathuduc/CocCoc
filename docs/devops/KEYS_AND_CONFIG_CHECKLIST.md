# Keys and config checklist — what the owner creates, where it goes, what wires it

**Status:** 2026-10-25, written from the [real-features inventory](../agent/REAL_FEATURES_INVENTORY_20261025.md) §5 and [phase breakdown](../agent/PHASE_BREAKDOWN_2_8.md). Owners of the mechanics: [Appwrite setup](APPWRITE_SETUP.md), [appwrite/AGENTS.md](../../appwrite/AGENTS.md), [ops/project.json](../../appwrite/ops/project.json), [env.public.example](../../infra/docker/env.public.example), [ADR-0018](../architecture/adr/0018-container-event-cache-runtime.md), [CI/CD](CI_CD.md), [operations](OPERATIONS.md). This page only lists what a human must create and where to put it. Never commit a value from this list; `.secrets/` and `.env*` are git-ignored.

## Where things go

| Place | What | Who writes it |
|---|---|---|
| `.secrets/real.env` (outside Git, on the operator machine) | every secret below, one `NAME=value` per line | owner |
| `.secrets/{learning,progress,ai}.env` | container runtime secrets (Phase 5 / VPS), loaded by [compose.local.yaml](../../infra/docker/compose.local.yaml) | owner, or generated by `setup:real` from `real.env` |
| Appwrite **function variables** (secret) | `COC_SERVICE_KEYS`, `COC_PROGRESS_CODE_SECRET`, provider keys | `pnpm appwrite:apply` (generated or copied write-only; never printed) |
| Appwrite **function variables** (plain) | URLs, flags, public keys | declared in `appwrite/ops/project.json`, applied by `appwrite:apply` |
| Appwrite **console only** | OAuth client secrets, custom SMTP, email templates | owner (the API cannot set these with a project key) |
| GitHub **environment `test` secrets** | `APPWRITE_TEST_API_KEY` (manual deploy workflow), release keystore, VPS deploy key | owner |
| Mobile **public** defines | [config/real.public.json](../../apps/mobile/config/real.public.json): endpoint, project ID, service URLs, recovery/verification URLs, OAuth on/off | committed (public values only) |

## The one command

**Target (built in Phase 2.0):**

```sh
pnpm setup:real -- --env-file .secrets/real.env          # add --dry-run to only print the plan
```

It will: validate that every key needed by the enabled features is present (and refuse otherwise) → `appwrite:plan`/`appwrite:test`/`schema:plan`/`schema:test` → `schema:apply` (M003 + M004 + later migrations) → `appwrite:apply` (variables, generated secrets, provider secrets write-only) → signed content publish → `appwrite:deploy` → `schema:check-live` + `appwrite:check-live` → `appwrite:probe-functions` → a redacted receipt under `docs/quality/`. It runs only against the TEST project, behind the same `ALLOW_*=reviewed-test-project` guards, and only when the owner asks.

**Until 2.0 lands, the equivalent today** (TEST project, owner-run; K5/K6/K7/K10 are still missing so Progress business routes will stay closed):

```sh
set -a; . ./.secrets/real.env; set +a
export APPWRITE_PROJECT_ENV=test ALLOW_SCHEMA_APPLY=reviewed-test-project \
       ALLOW_APPWRITE_APPLY=reviewed-test-project ALLOW_LIVE_PROBE=reviewed-test-project
pnpm schema:plan && pnpm schema:apply && pnpm schema:check-live \
  && pnpm appwrite:apply && pnpm appwrite:deploy && pnpm appwrite:check-live \
  && pnpm appwrite:probe-functions
```

Provider secrets (K15/K16) must today be typed into the Appwrite console as secret function variables; `appwrite:apply` only reports them as missing.

## Steps that cannot be automated

- **OAuth consoles** (Google/Facebook/Apple): consent screen, client creation, secrets into the Appwrite console. Google review may be needed for production scopes.
- **Custom SMTP / email templates** in the Appwrite console; DNS (SPF/DKIM) for the sender domain.
- **Domain + DNS + `assetlinks.json` hosting** for recovery links / App Links; TLS for the VPS.
- **Paid/free-tier sign-ups**: Azure Speech, Gemini, SMS, VPS, managed broker/Redis — accounts, billing caps and budget approval.
- **Appwrite plan/expiry decisions** and the export/restore rehearsal before the Education term ends.
- **Physical Android device** tests: notifications, widget, audio focus/Bluetooth, microphone, OAuth/app-link return, performance.
- **iOS**: Apple Developer team, signing certificates, a macOS build — out of the Android-first scope.
- **GitHub branch protection** and environment approvals (repository-owner settings).
- **Explicit go-ahead** for every live step (`schema:apply`, `appwrite:apply/deploy`, probes) — by project rule these never run without the owner's request.
