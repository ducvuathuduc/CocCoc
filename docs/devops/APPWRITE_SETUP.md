# Appwrite Cloud integration admission

Design uses two admitted Education projects at most: development and test/staging; production remains unconfigured. If entitlement does not permit two projects, use one test project with strict synthetic fixtures and no live learner data. After Education expiry, a three-service Cloud demo may exceed the Free Function count; the local three-adapter fallback preserves boundaries but does not prove cloud coursework requirements.

1. Student/platform owner privately records organization term end, project/region, current plan limits and spending cap. Resolve before 2026-11-01 if already beyond the six-month term. Export and rehearse restore before changing plan; never assume disabling preserves login access.
2. Register Android package and later iOS bundle `com.cocenglish.cocenglish`; email/password baseline first, OAuth callback/platform configuration only with real access. Verify Account.get from each service's per-request JWT client.
3. Review the full 62-table declaration (M003 adds p_promo_codes, p_promo_redemptions and p_ad_events; it is not yet applied) and the learning-assets bucket in [schema](../../appwrite/schema/foundation.json). `pnpm schema:plan` makes no network call: it re-derives every table, column, index and permission from the [data model](../data/DATA_MODEL.md) and [permissions](../data/PERMISSIONS.md), fails on any drift or invented column, resolves the SDK methods the apply path would call against the pinned node-appwrite, and prints the plan with a declaration SHA-256. `pnpm schema:test` runs the offline drift, parser and apply-guard tests. After a reviewed DATA_MODEL/PERMISSIONS change, `pnpm schema:declare` regenerates the declaration (and `CANONICAL_TABLE_COUNT` in appwrite/scripts/schema-lib.mjs must be updated in the same change). Implicit sizes and types follow the conventions recorded in the declaration. A declaration is not live evidence: column/index availability, row-width limits and permission probes still need step 4.
4. On an explicitly authorized test-project setup task, apply with private process environment: APPWRITE_PROJECT_ENV=test, ALLOW_SCHEMA_APPLY=reviewed-test-project and APPWRITE_ENDPOINT/APPWRITE_PROJECT_ID/APPWRITE_API_KEY. `pnpm schema:apply` snapshots the live project, creates only missing resources (database, tables, columns, then indexes once columns are available, then the bucket), waits for availability and prints `APPLIED` or `NO_CHANGES` with created counts; any existing drift aborts before a change and is reviewed, never dropped; extra live resources are reported, never deleted. A rerun resumes where a pending column/index stopped. `pnpm schema:check-live` (APPWRITE_PROJECT_ENV=test plus endpoint/project/key; read-only) compares every live table permission/rowSecurity, column type family/size/required/enum elements/integer bounds, index type/columns and bucket security with the declaration and fails on missing, drift, extra or pending. Then `pnpm appwrite:probe` (ALLOW_LIVE_PROBE=reviewed-test-project) runs the live auth/transaction/permission/runtime probes below; it creates two synthetic users and deletes them and every probe row afterwards. Client-side probe calls carry only the user JWT/session over a direct connection: a request that also carries a server key would run as the server and prove nothing.
5. Deploy each owner's bundled artifact to its own Function ID using reviewed per-service descriptors. The JSON files are project setup descriptors, not a claim of valid Appwrite CLI import syntax. Console fields are runtime node-22, entrypoint dist/function.mjs, timeout30, explicit execute/scopes; current descriptors disabled/empty. Business adapters must be implemented and admitted before enablement.
6. Configure individual owner secrets, HMAC key rotation and schedule/event execution roles; no service trusts caller trigger/user-id headers. Dispatcher is a Learning role, not a fourth service. Test unsigned/expired/tampered signature, scheduler spoofing, revoked JWT, wrong owner and cross-user access.
7. Run transaction conflicts, partial-commit prevention, outbox failure/ack-loss/dead-letter, schema drift and immutable seed publish probes. Record project/runtime/SDK/result without keys or user recordings. [Release gate](../quality/RELEASE_GATE.md) blocks authority claims until this evidence exists.

Auth uses Appwrite Account; direct client data writes denied. Published Storage assets may be public/read-only; private recordings owner-controlled with TTL. Server keys cannot enforce hard per-table isolation inside one project; owner allowlists and negative tests are mandatory. Functions are independent deploy units, not a managed database relabeled as a custom microservice.

Current SDK node-appwrite29.2.0 compiles the Account client usage. Public [Cloud runtime list](https://appwrite.io/docs/products/functions/runtimes) includes node-22; the admitted test project offers node-22 (live evidence below), production plan remains ACCOUNT-DEPENDENT. [Transactions](https://appwrite.io/docs/products/databases/tablesdb/transactions) document staging/commit/conflicts; schema APIs are not transactional migrations. No project, resources, credentials, deployment or integration success is fabricated.

## Live evidence: admitted test project (2026-10-12)

Project `coccoc-test` (id 6acc656d0025cc57bd81), Appwrite Cloud region sgp (`https://sgp.cloud.appwrite.io/v1`, server 2.4.0), Education plan; SDK node-appwrite 29.2.0, Node 22. No keys, JWTs or user data are recorded. Functions were not deployed (project has 0 functions).

- Schema apply, declaration SHA-256 16394f13bff2a9d9f37d0e24224a0c956997b70c519636ec55644be6604970b0: first `schema:apply` APPLIED 1 database (`cocenglish`), 59 tables, 630 columns, 108 indexes (60 unique), 1 bucket (`learning-assets`), all available with no column/index failure; second run NO_CHANGES (0 created); `schema:check-live` PASS (0 missing, 0 drift, 0 extra, 0 pending), also after the probes.
- Live type names: varchar columns report `varchar` (+size), text/mediumtext report `text`/`mediumtext`, enums report `string` + format `enum`, integer/boolean/datetime as named; index columns report `lengths` 0. No declared size had to change: the widest table (p_profiles, 4,366 varchar chars) and every index fit the Cloud row-width and index-length limits.
- Auth: email/password session through the Account API (project header only) and a JWT from that session; `COC_LIVE_APPWRITE_PROBE=1` Account.get test passed (valid JWT maps to the user id; tampered JWT rejected); JWT of a deleted session rejected (401).
- TablesDB transactions are available on this plan: staged row invisible before commit and visible after; rollback discards; a unique-index violation inside a transaction fails the commit with 409 `transaction_conflict` and the sibling staged row is not committed (no partial commit); two transactions updating one row: first commits, second gets 409 `transaction_conflict`; an out-of-band write after staging makes the commit fail with 409. Services still keep revision compare-and-set as the documented contract.
- Permissions (user JWT, no key): valid row creates on p_blocks, p_notifications and p_zone_history are denied (401 `user_unauthorized`); listRows without a row grant returns 0 rows; a p_notifications row with read(Role.user(owner)) is readable by its owner only (other user 404), and owner update/delete are denied (401); client upload to `learning-assets` is denied (401).
- Runtime: `/functions/runtimes` (guest-scoped endpoint; server keys lack the `public` scope it needs) lists node-22 (also node-16.0, 18.0, 24, 25, 26).
