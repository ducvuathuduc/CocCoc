# ASP.NET Core migration — in progress

This directory contains the replacement runtime approved in [ADR-0020](../docs/architecture/adr/0020-dotnet-service-migration.md). Node remains the active baseline. This is not a complete replacement or a deployment-ready backend yet.

```powershell

```

The gated Appwrite persistence and Storage probes are prepared for `coccoc-test`. Store only the server key as `APPWRITE_API_KEY=...` in the ignored root `.secrets/real.env`, then run `& .\backend-dotnet\tools\test-appwrite-live.ps1` from the repository root. The runner pins the endpoint, project and database to the test target, imports only this key, restores the process environment afterwards, and runs only the gated probe suites. It creates and removes synthetic `l_active_slots`, `p_profiles` and `a_active_slots` rows, plus one tiny `learning-assets` file that it downloads through the .NET adapter before deleting. Grant the key the row access required by the persistence probes and `files.read` plus `files.write` for the Storage round-trip; the probe does not make the file public. All live probes stay skipped in ordinary local and CI test runs. Never paste the key into chat or source control.

The solution has three independent API hosts, a shared security/persistence library, contracts and three test projects. The canonical OpenAPI and storage declarations are embedded directly; the generator checks all 91 declared operations and 52 error codes without modifying Flutter contracts.

## Migration constraints

Keep Flutter, Appwrite identity/data/storage, wire contracts, deterministic IDs and service-owned writes. Never run Node and .NET writers/workers concurrently for the same owner during cutover. Preserve Node for rollback. Do not reset learner data, introduce shadow writes, enable paid providers, apply cloud schema, deploy or push as an implicit consequence of local migration work.

Next: expand Node/.NET parity beyond the selected Progress, Learning and disabled-speech AI fixtures; then run durable Appwrite, mixed-runtime, worker-hosting and Flutter/native acceptance against isolated test data before any cutover.

### .NET recorded speech remains gated

The .NET host now contains server-side adapters for Azure Pronunciation Assessment, AssemblyAI transcription and Deepgram transcription. The provider mode must be explicitly selected with COC_AI_PROVIDER=speech, the separate COC_AI_SPEECH_ADMITTED=reviewed-device-quality-privacy-cost gate must be approved, and at least one valid provider credential must be configured. Azure scoring also requires its region. No deployment configuration in this repository sets the new speech admission gate.

The gate stays unset until target-device recording, pronunciation quality, privacy/retention and service-cost checks are complete. Local tests use fake HTTP handlers only; they make no provider requests. Azure scores are returned only for successful dedicated assessments with nonempty transcript, finite accuracy/completeness and acceptable returned confidence. Transcription fallbacks never invent pronunciation metrics. Azure calls reserve a project-wide daily allowance (default 573 seconds); user recording remains bounded to 600 seconds/day. Requests send audio transiently and persist only its hash plus bounded assessment results.
