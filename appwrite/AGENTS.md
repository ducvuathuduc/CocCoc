# Appwrite schema and scripts

`appwrite/` is the only home for Appwrite resources. There is no `infrastructure/` folder.

```text
appwrite/
  schema/foundation.json     declared TablesDB tables/columns/indexes/permissions + buckets (generated)
  scripts/schema-lib.mjs     derivation from docs + CANONICAL_TABLE_COUNT
  scripts/schema-declare.mjs regenerate foundation.json from docs/data/DATA_MODEL.md + PERMISSIONS.md
  scripts/schema.mjs         dry-run plan (default) | --apply | --check-live
  scripts/seed.mjs           typed catalog seed validation against OpenAPI
  scripts/live-probe.mjs     gated live permission/transaction probes
  appwrite.config.json       Appwrite CLI config: one Function per service (coc-learning/progress/ai)
  ops/project.json           auth methods/policies, platforms, function variables/secrets, domains, schedules
  runtime/main.mjs           Function entrypoint adapter over services/<svc>/dist/function.mjs
  scripts/ops-lib.mjs        pure validation/diff/keyring helpers
  scripts/ops.mjs            plan (default) | --apply | --check-live | --deploy | --health | --probe
  seeds/catalog.json
  test/schema.test.mjs
  test/ops.test.mjs
```

## Functions and project settings

Edit `appwrite.config.json` (function settings) or `ops/project.json` (everything else), run `pnpm appwrite:plan && pnpm appwrite:test`, then on the reviewed test project `pnpm appwrite:apply`, `pnpm appwrite:deploy` and `pnpm appwrite:check-live`. Run the CLI from `appwrite/` (e.g. `appwrite functions list`, `appwrite functions create-execution --function-id coc-ai --path /health --method GET`). Never put a secret in either file: `COC_SERVICE_KEYS` is generated by apply and stored only as a secret function variable. A service code push redeploys with `pnpm appwrite:deploy -- --service <svc>`.

## Changing a table

1. Edit [DATA_MODEL](../docs/data/DATA_MODEL.md) and [PERMISSIONS](../docs/data/PERMISSIONS.md), the owner docs.
2. Update `CANONICAL_TABLE_COUNT` in `scripts/schema-lib.mjs` if the table count changes.
3. Run `pnpm schema:declare`, then `pnpm schema:plan && pnpm schema:test && pnpm seed:check`.
4. Commit the docs, the declaration and the tests together. `schema/` is an exclusive change area.

## Live commands (never in CI, never without an explicit request)

Run `pnpm schema:apply`, `pnpm schema:check-live`, `pnpm appwrite:probe` or the `appwrite:apply/deploy/check-live/health/probe-functions` commands only against the reviewed **test** project. They require these environment variables:

- `APPWRITE_PROJECT_ENV=test`
- `ALLOW_SCHEMA_APPLY=reviewed-test-project` (for schema apply), `ALLOW_APPWRITE_APPLY=reviewed-test-project` (for appwrite:apply/deploy) or `ALLOW_LIVE_PROBE=reviewed-test-project` (for probes)
- `APPWRITE_ENDPOINT`, `APPWRITE_PROJECT_ID` and `APPWRITE_API_KEY` in the process environment, never in files

Apply is idempotent and additive. Never run a destructive reset.
